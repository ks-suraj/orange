# Synthetic incident scenarios

Generated by `python scripts/generate_scenarios.py` (deterministic, seeded). Do not edit the JSON by hand;
change the specs in the generator and regenerate. The current version is **v2.1**: `data/MANIFEST.json` holds
SHA-256 hashes of every file (computed on LF-normalised content; files are always written with LF), and
`tests/test_dataset.py` fails if the data and the manifest diverge.
Background log volume follows each service's request rate, and success lines thin out with its error rate.

Each `S??/` folder holds what the tools serve:

| File | Served by |
|---|---|
| `scenario.json` | the incident brief given to agents, plus tool fault injection (hidden from agents) |
| `logs.json` | `query_logs` (~300 lines: background traffic plus injected signals) |
| `metrics.json` | `query_metrics` (46 series, 5-minute resolution, noisy baselines) |
| `changes.json` | `get_change_history` (7 days: background changes plus scenario changes) |
| `topology.json` | `get_dependencies` (shared service graph and per-scenario health checks) |
| `past_incidents.json` | `search_past_incidents` (generic postmortems plus scenario-specific ones) |

Ground truth is kept separately in `data/ground_truth/S??.json` and is read only by the evaluator:
the accepted root-cause components and categories, key-evidence id groups, misleading-evidence ids and decoy
hypotheses.
